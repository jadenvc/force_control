# Minimal MuJoCo FlipUp

This folder contains only the UR5e + WSG50 FlipUp environment and its scripted
heuristic. It does not depend on `PyriteEnvSuites`, `PyriteUtility`, `PyriteML`,
Ray, Torch, Zarr, Plotly, OpenCV, or any dataset/recording code.

The task randomizes a flat book next to a bookend, approaches it with the
closed WSG50, and follows a scripted 90-degree pivoting trajectory. Success
means that the book's long axis finishes within 15 degrees of vertical.

The scene uses the original PyriteEnvSuites UR5e, WSG50, RealSense D435i,
table, book, bookend, and reference-frame models, including their original
visual meshes and textures.

Collision filtering allows only robot-book and book-bookend-support contact.
Robot self-contact and all contacts involving the decorative table, floor, or
reference frame are disabled.

## Install

Linux and Python 3.10 or newer are recommended.

```bash
cd flipup_minimal
python3 -m venv .venv
source .venv/bin/activate
python -m pip install --upgrade pip
python -m pip install -e .
```

## Run

Run seed 0 with the interactive MuJoCo viewer:

```bash
python run_flipup.py --seed 0
```

Run without a viewer, which is useful on a server:

```bash
python run_flipup.py --seed 0 --no-viewer
```

After installation, this equivalent command is also available:

```bash
flipup-demo --seed 0
```

A successful run prints output similar to:

```text
SUCCESS: final angle=1.14 deg
```

Different seeds change the initial scene. As in the original data-generation
runner, the heuristic can fail on some randomized scenes; seed `0` is the
validated quick-start example.

## Physical-property controls

Open a setup window with draggable sliders for book mass, sliding/torsional/
rolling friction, length, width, and thickness:

```bash
python run_flipup.py --seed 0 --physics-controls
```

The window's **Randomize** button uniformly samples all sliders from the ranges
shown beside them. **Reset defaults** restores the original asset values. The
selected values are applied before MuJoCo builds the model, so collision size,
rendered mesh scale, mass, and inertia stay consistent.

For reproducible domain randomization without the setup window:

```bash
python run_flipup.py --seed 2 --randomize-physics --no-viewer
```

The seed controls both the scene and physical-property samples. The two random
streams are kept separate, so enabling physical randomization does not change
the scene pose generated by an existing seed. The sampled values are printed at
the beginning of every run. The default ranges intentionally include harder
configurations, so the scripted heuristic is not expected to succeed on every
randomized sample.

Individual values can also be set from the command line (dimensions are in
meters):

```bash
python run_flipup.py --book-mass 0.8 --book-friction 0.2 \
  --book-length 0.18 --book-width 0.09 --book-thickness 0.02
```

Exact command-line values override sampled ones, so they can be combined with
`--randomize-physics` to hold selected properties fixed.

The same features are available from Python:

```python
from flipup import PhysicalProperties, run_flipup

result = run_flipup(
    seed=4,
    show_viewer=False,
    physical_properties=PhysicalProperties(
        mass_kg=0.8,
        sliding_friction=0.2,
        length_m=0.18,
        width_m=0.09,
        thickness_m=0.02,
    ),
)

# Or sample every physical property from the default ranges.
randomized_result = run_flipup(
    seed=4,
    show_viewer=False,
    randomize_physics=True,
)
```

## Contents

- `flipup/environment.py`: MuJoCo model assembly and task-space controller.
- `flipup/heuristic.py`: scene randomization, waypoints, rollout, and success check.
- `flipup/physical_properties.py`: validated values and randomization ranges.
- `flipup/controls.py`: optional draggable slider setup window.
- `flipup/trajectory.py`: compact TOPPRA trajectory parameterization.
- `flipup/assets/`: original visual and physics assets needed by this task only.
- `run_flipup.py`: executable entry point.

Learning code, recording code, datasets, and unrelated environments are
deliberately omitted. The archive is larger than a primitive-only scene
because the original high-resolution robot and camera meshes are included.

## Troubleshooting

If the viewer cannot open, check that the machine has a working desktop/OpenGL
session, or use `--no-viewer`.

If `--physics-controls` reports that `tkinter` is missing, install the Tk
package for your Python distribution (for example, `python3-tk` on Ubuntu).

On a headless machine that needs offscreen MuJoCo rendering for custom
extensions, set `MUJOCO_GL=egl`.
